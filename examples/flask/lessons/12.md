# 12 · 蓝图规则、会话实现与请求分发

> 模型生成，需人工审阅。仅依据静态源码片段；图中的边表示可解析的静态关系。

## 从源码理解

- **Blueprint.add_url_rule**：这是蓝图上的路由注册方法，它先校验 endpoint 和视图函数名不能含点号，否则抛出 ValueError；随后并不立即注册，而是通过 self.record 记录一个延迟函数，等蓝图注册到应用时才真正调用应用的 add_url_rule。阅读时注意它把实际工作推迟到注册阶段。 [Blueprint.add_url_rule](src/flask/sansio/blueprints.py:413)

- **Blueprint.make_setup_state**：该方法创建一个 BlueprintSetupState 实例，把蓝图自身、应用和选项打包起来，稍后传给注册回调函数。文档说明子类可重写它以返回自定义的 setup state 子类，可见它是注册流程中的可扩展点。 [Blueprint.make_setup_state](src/flask/sansio/blueprints.py:246)

- **Blueprint.record_once**：record_once 与 record 类似，但把传入函数包在 wrapper 里，仅当 state.first_registration 为真时才调用原函数。也就是说蓝图第二次注册到应用时该函数不会再执行，适合只应运行一次的初始化逻辑。 [Blueprint.record_once](src/flask/sansio/blueprints.py:233)

- **Blueprint**：Blueprint 继承 Scaffold，代表一组可稍后注册到真实应用上的路由与相关函数，允许在尚无应用对象时先定义功能。构造函数校验 name 非空且不含点号，并保存 url_prefix、subdomain 等，同时初始化 deferred_functions 列表用于存放延迟注册函数。 [Blueprint](src/flask/sansio/blueprints.py:119)

- **BlueprintSetupState.add_url_rule**：这是注册阶段真正拼接路由的地方：若设置了 url_prefix，就把前缀与规则用斜杠连接；endpoint 为空时从视图函数名推导。最终调用 app.add_url_rule，并把 endpoint 拼成带蓝图名前缀的形式，从而把蓝图路由落到应用上。 [BlueprintSetupState.add_url_rule](src/flask/sansio/blueprints.py:87)

- **Scaffold.register_error_handler**：该方法是不用装饰器的错误处理器注册入口，接收异常类或状态码以及处理函数。它先用 _get_exc_class_and_code 解析出异常类与状态码，再把函数存入 error_handler_spec 中对应位置。 [Scaffold.register_error_handler](src/flask/sansio/scaffold.py:642)

- **find_package**：find_package 用于找出某个包安装所在的前缀目录和它将被导入的路径。它先取得包路径，若位于 sys.prefix 下则返回该前缀；否则检查是否在 site-packages 中，按 Windows、Unix 等目录结构推断前缀，未安装时前缀返回 None。 [find_package](src/flask/sansio/scaffold.py:754)

- **SecureCookieSession**：SecureCookieSession 是基于签名 cookie 的会话基类，继承 CallbackDict 和 SessionMixin。它用 modified 和 accessed 标记数据是否被修改或读取，读取或写入时会把 accessed 置真；文档说明它无法可靠判断会话是否为新建，因此 new 恒为 False。 [SecureCookieSession](src/flask/sessions.py:52)

- **SecureCookieSessionInterface.open_session**：open_session 在请求开始时从 cookie 恢复会话：先取签名序列化器，若应用没有 secret_key 则返回 None。它读取对应 cookie，没有值就返回空会话；有值则用最大存活时间校验签名并反序列化，签名无效时返回空会话。 [SecureCookieSessionInterface.open_session](src/flask/sessions.py:337)

- **SecureCookieSessionInterface.save_session**：save_session 在响应阶段把会话写回 cookie：先读取名称、域、路径等 cookie 配置，若会话被访问过则添加 Vary: Cookie 头。会话为空时，若曾被修改则删除 cookie 并返回；否则按 should_set_cookie 判断，序列化会话数据后调用 set_cookie 写入。 [SecureCookieSessionInterface.save_session](src/flask/sessions.py:351)

- **SecureCookieSessionInterface**：这是默认的会话接口，通过 itsdangerous 把会话存进签名 cookie。类属性定义了盐值、摘要方法、密钥派生方式、序列化器和会话类；get_signing_serializer 在无 secret_key 时返回 None，否则把回退密钥与当前密钥一起构造 URLSafeTimedSerializer。 [SecureCookieSessionInterface](src/flask/sessions.py:298)

- **render_template**：render_template 按名称渲染模板并传入上下文变量，名称也可以是模板列表以按序选择。它从 current_app 取得当前应用，用 jinja_env.get_or_select_template 选出模板，再交给 _render 完成渲染并返回字符串。 [render_template](src/flask/templating.py:138)

- **render_template_string**：render_template_string 直接从给定的源码字符串渲染模板，而不是从文件加载。它同样取得当前应用，用 jinja_env.from_string 构造模板，再调用 _render 返回渲染结果。 [render_template_string](src/flask/templating.py:153)

- **FlaskCliRunner.invoke**：FlaskCliRunner.invoke 在隔离环境中调用 CLI 命令，参数与 click 的 CliRunner.invoke 一致。若未传入 cli 则使用 self.app.cli，若未提供 obj 则注入一个以当前应用创建应用的 ScriptInfo，然后交给父类执行。 [FlaskCliRunner.invoke](src/flask/testing.py:275)

- **MethodView**：MethodView 继承 View，把请求方法分派到同名实例方法，例如 get 处理 GET 请求。__init_subclass__ 会在子类未显式定义 methods 时，根据基类和已实现的 http 方法名自动收集允许的方法；dispatch_request 按 request.method 取方法，HEAD 无处理器时回退到 get。 [MethodView](src/flask/views.py:138)

- **Request.blueprints**：Request.blueprints 返回当前蓝图及其父蓝图的注册名列表。若当前没有蓝图（blueprint 为 None）则返回空列表，否则用 _split_blueprint_path 拆分蓝图名得到层级列表。 [Request.blueprints](src/flask/wrappers.py:181)

- **Flask.dispatch_request**：dispatch_request 负责请求分发：若存在路由异常则抛出，若规则支持自动 OPTIONS 且请求为 OPTIONS 则返回默认 OPTIONS 响应。否则从 view_functions 中按 rule.endpoint 取出视图函数，用 ensure_sync 包装后以视图参数调用并返回其结果。 [Flask.dispatch_request](src/flask/app.py:879)

- **Flask.do_teardown_appcontext**：do_teardown_appcontext 在应用上下文弹出前调用，用于执行应用上下文清理函数。若未显式传入异常则从 sys.exc_info 取当前异常，然后按注册的逆序逐个调用 teardown_appcontext_funcs，最后发送 appcontext_tearing_down 信号。 [Flask.do_teardown_appcontext](src/flask/app.py:1360)

- **Flask.do_teardown_request**：do_teardown_request 在请求分发完成、响应返回后、请求上下文弹出前调用。它按 request.blueprints 顺序再追加 None，对每个名字逆序调用对应的 teardown_request_funcs，最后发送 request_tearing_down 信号。 [Flask.do_teardown_request](src/flask/app.py:1326)

- **Flask.handle_http_exception**：handle_http_exception 处理 HTTP 异常：若异常没有状态码或是内部 RoutingException 则直接返回异常本身。否则用 _find_error_handler 结合 request.blueprints 查找已注册的错误处理器，找到就调用它，找不到则把异常作为响应返回。 [Flask.handle_http_exception](src/flask/app.py:744)

- **Flask.preprocess_request**：preprocess_request 在请求分发前运行：先按应用与蓝图顺序调用 url_value_preprocessors 处理 endpoint 和视图参数，再调用 before_request_funcs。任一 before 处理器返回非 None 值时立即返回该值，否则返回 None 继续正常分发。 [Flask.preprocess_request](src/flask/app.py:1271)

- **Flask.process_response**：process_response 在响应发送前修改响应：先执行请求上下文中的 after_request 函数，再按 request.blueprints 顺序逆序调用各蓝图的 after_request 函数。若会话不是空会话，则调用 session_interface.save_session 把会话写入响应，最后返回响应。 [Flask.process_response](src/flask/app.py:1298)

- **Flask.send_static_file**：send_static_file 是用于从 static_folder 提供文件的视图函数，若未设置静态目录则抛出 RuntimeError。它先通过 get_send_file_max_age 取得缓存时长，再调用 send_from_directory 从静态目录发送指定文件。 [Flask.send_static_file](src/flask/app.py:308)

- **Flask.test_request_context**：test_request_context 根据给定参数构造 WSGI 环境并创建 RequestContext，主要用于测试中在不分发完整请求的情况下使用请求数据。它用 EnvironBuilder 构建环境，返回 request_context 的结果，并在 finally 中关闭 builder。 [Flask.test_request_context](src/flask/app.py:1423)
